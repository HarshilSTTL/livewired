### [2026-08-06] | FIX (SP+SCHEMA) | update_event_v2 'this' scope changed collaborators for the whole recurring series

**What happened:**
User reported: updating a recurring event with `p_scope='this'` and a new `p_collaborator_ids` list changed the collaborator for **every occurrence** in the series, not just the selected one.

**Root cause:**
`event_collaborators` had no per-occurrence concept at all — every read and write path (`update_event_v2`, `get_event_by_id`, `get_profile_events_v2`, `get_event_list`) resolved collaborator rows via `COALESCE(parent_event_id, event_id)`, i.e. always the series parent. `update_event_v2`'s "SHARED: collaborator SYNC" block ran unconditionally against `v_target_parent_id` regardless of `v_scope`, same as `p_is_collaborative` (which is correctly documented as always parent-level) — but collaborators were never meant to be parent-only.

**Fix — added a `collaborators_overridden` flag on `event_mst` (mirrors the existing `is_overridden` pattern used for scalar/platform overrides):**
- `scope='this'` → collaborator sync now targets the occurrence itself (`event_id = p_event_id`) and sets `collaborators_overridden = true` on that row.
- `scope='all'` → still targets the series parent, but first clears any prior per-occurrence overrides (deletes overridden `event_collaborators` rows on children, resets `collaborators_overridden = false`) so children go back to inheriting the series list.
- All read paths now check `collaborators_overridden`: `true` → use the occurrence's own collaborator rows, `false` → fall back to the series parent's, same `CASE` pattern already used for `event_platforms`.

**Functions changed — each got a new version + a new function name/endpoint, per this repo's convention (see `get_profile_platforms_v2_1`) of bumping the name on any functional change and keeping the old one live for existing callers:**

| Function             | Old (still live)        | New (current)                 | Change                                                                                                                                                                                  |
| -------------------- | ----------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `update_event`       | `update_event_v2`       | **`update_event_v2_1`**       | Collaborator sync section made scope-aware; new `v_collab_target_id` var; clears prior overrides on `scope='all'`; sets `collaborators_overridden` on `scope='this'`. Params unchanged. |
| `get_event_by_id`    | `get_event_by_id` (v1)  | **`get_event_by_id_v2`**      | Collaborators subquery now branches on `collaborators_overridden` instead of always using `COALESCE(parent_event_id, event_id)`.                                                        |
| `get_profile_events` | `get_profile_events_v2` | **`get_profile_events_v2_1`** | Same collaborators-subquery fix, plus the "is this user an accepted collaborator" membership filter updated to check the occurrence's own list when overridden.                         |
| `get_event_list`     | `get_event_list` (v1)   | **`get_event_list_v2`**       | Same two fixes applied identically across all 4 date branches (PAST / LIVE / TODAY / FUTURE).                                                                                           |

Old versions are kept in each doc under "Previous"/"Deprecated" — existing app builds calling the old endpoints keep working unchanged until the client is updated to call the new ones.

**Not changed (already occurrence-agnostic by design):**
- `invite_collaborator` (deprecated), `remove_collaborator`, `respond_collaborator_invite` — these already operate on whatever `event_id` the caller passes (no `COALESCE`), so they work against either a parent or an overridden occurrence row as-is. No code change needed, just a note that callers must pass the correct `event_id` for the intended scope.
- `get_profile_events` v1 (deprecated) — untouched; only v2 → v2.1 was patched.

**Schema migration required before deploying the new SPs:**
```sql
ALTER TABLE public.event_mst
    ADD COLUMN IF NOT EXISTS collaborators_overridden boolean NOT NULL DEFAULT false;

NOTIFY pgrst, 'reload schema';
```

**Deployment note:** These are brand-new function names (`update_event_v2_1`, `get_event_by_id_v2`, `get_profile_events_v2_1`, `get_event_list_v2`), not overload replacements — no need to drop anything first, and no risk to the currently-deployed old versions. Run the `ALTER TABLE` migration first, deploy the 4 new functions, then update the client app to call the new `/rpc/*` endpoints. `NOTIFY pgrst, 'reload schema';` after deploying.

**Correction (same day):** The `scope='all'` override-clearing step in `update_event_v2_1` originally used `DELETE FROM event_collaborators ...` to clear per-occurrence overrides. That's a genuine hard delete, and it was inconsistent with the rest of the same function — `event_collaborators` has `is_deleted`/`deleted_at` columns and every other removal in this function (and everywhere else in the codebase) soft-deletes via those. Fixed to `UPDATE event_collaborators SET is_deleted = true, deleted_at = now() ... WHERE is_deleted = false`, matching the existing convention. (`event_platforms` and the recurring-regen `DELETE FROM event_mst` elsewhere in this function are correctly hard deletes — those tables have no soft-delete columns; only the new `event_collaborators` line was wrong.)
