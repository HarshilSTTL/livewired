### [2026-08-20] | DOCS + FEAT | Forgot Password — switched from magic-link to OTP-based recovery

**What changed:**
`docs/remaining_apis.md` previously documented `forgot_password` as
`supabase.auth.resetPasswordForEmail(email)` sending a magic link. Product
wants an OTP-based flow instead (user enters a 6-digit code sent by email,
not a link) for the sign-in page's forgot-password screen.

**Decision — use Supabase Auth's built-in recovery OTP, not a custom build:**
Considered two options:
1. **Supabase built-in OTP** (chosen) — `resetPasswordForEmail` +
   `verifyOTP(type: recovery)` + `updateUser({password})`, only requiring a
   change to the Reset Password email template (use `{{ .Token }}` instead
   of `{{ .ConfirmationURL }}`). No new table, SQL function, or Edge
   Function.
2. Fully custom OTP system — new `password_reset_otps` table, custom
   `request_password_otp`/`verify_and_reset_password_otp` SQL RPCs, plus a
   service-role Edge Function to actually change the Supabase Auth password
   (since `public.users` doesn't own password hashes — see
   `schema/tables/02_users.md`). Rejected: more code to build and secure,
   duplicates OTP generation/hashing/expiry/rate-limiting Supabase Auth
   already does safely, and breaks the repo's established pattern of
   letting Supabase Auth own passwords entirely.

**Files:**
- [[docs/api/auth/forgot_password.md]] — new, full step-by-step flow for the mobile team
- [[docs/remaining_apis.md]] — `forgot_password` row updated to point to the new doc
