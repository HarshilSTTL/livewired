### [2026-08-31] | FIX | `update_profile` never removed a deleted platform URL

**What changed:**
Removing a platform/URL from a profile (dropping it from `p_platforms` and
calling `update_profile`) and then re-fetching via `get_profile_by_id_v2_1`
still showed the removed URL. The documented contract
(`docs/api/profiles/update_profile.md`) describes `p_platforms` as a
**replace-all** pattern — rows missing from the array should be cleared — but
the SQL only ever upserted: it looped the incoming array and UPDATE-or-INSERTed
each entry, with no step to soft-delete rows whose `platform_id` was no longer
present. So a removed platform stayed `is_deleted = false` in
`creator_platform_accounts` and kept showing up on fetch.

**Fixed:**
- `update_profile` — before the upsert loop, now soft-deletes
  (`is_deleted = true`) any existing `creator_platform_accounts` row for the
  profile whose `platform_id` is not present in the incoming `p_platforms`
  array. This also makes `p_platforms = []` correctly clear all platform rows,
  matching the documented behaviour.
- Same function/endpoint name (`update_profile`) — redeploy only, no client
  change.

**Files:**
- [[functions/profiles/update_profile.md]] — added soft-delete step + updated header comment
- [[docs/api/profiles/update_profile.md]] — logic-flow step 8 updated to mention the delete
