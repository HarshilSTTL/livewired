# 📋 LiveWired — Update Log · 2026-09-30

[2026-09-30 10:28] | FIX | get_following_list respects show_followers

`get_following_list` returned the follower count even when a profile had "Show Follower Count" off. `followers` is now `null` when `show_followers = false` (same pattern as `get_creators`).

**Files:** `functions/follow/get_following_list.md`, `docs/api/follow/get_following_list.md`

**Still needed:** run the updated `CREATE OR REPLACE FUNCTION get_following_list(...)` in the Supabase SQL editor, then `NOTIFY pgrst, 'reload schema';`. No client signature change; client must handle `followers: null`.

[2026-09-30 10:45] | FIX | get_following_list ordered alphabetically

`get_following_list` now orders results by `lower(profile_name) ASC` (previously most recently followed first), so the Following page displays alphabetically.

**Files:** `functions/follow/get_following_list.md`, `docs/api/follow/get_following_list.md`

**Still needed:** run the updated `CREATE OR REPLACE FUNCTION get_following_list(...)` in the Supabase SQL editor, then `NOTIFY pgrst, 'reload schema';`. No client change.

[2026-09-30 10:55] | SP | respond_collaborator_invite_v3 clears the invitee's invite notification

Accepting or declining a collaborator invite now marks the invitee's own `collaborator_invite` notification for that event as `is_cleared = true`, so it disappears from their notifications page (`get_notifications` already filters cleared rows). Matched on `user_id` + `data->>'event_id'`. v2 is deprecated.

**Files:** `functions/events/respond_collaborator_invite.md`, `docs/api/events/respond_collaborator_invite.md`

**Still needed:** run the new `CREATE OR REPLACE FUNCTION respond_collaborator_invite_v3(...)` in the Supabase SQL editor, then `NOTIFY pgrst, 'reload schema';`. Client must switch the RPC call from `respond_collaborator_invite_v2` to `_v3` (same params) and refresh the notifications list after responding.
