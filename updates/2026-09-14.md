### [2026-09-14 15:40] | FIX | `get_following_list` showed non-streaming icons next to avatar — QC on Following page

**What changed:**
QC flagged that the Following page shows extra icons next to a creator's
avatar (beyond streaming platform logos), unlike the Creator Search page
which only shows YouTube/Twitch/Kick/Rumble icons there. Root cause:
`get_following_list`'s `platforms` field returned *all* linked platforms
(including additional links like Patreon/Discord), unfiltered — while
`search_profiles_v2`/`v2_1` already filter to main streaming platform IDs
(1-4) for the same avatar-adjacent icon row.

**Fixed:**
- `get_following_list` — `platforms` subquery now filters to
  `p.plat_id IN (1, 2, 3, 4)`, matching `search_profiles_v2` so the
  Following page and Creator Search page render the same icon set.

- [[docs/api/follow/get_following_list.md]] — documented the filtered behavior

### [2026-09-14] | FIX | Deleted profile names stayed reserved forever — `create_profile_v2` / `update_profile_v2`

**What changed:**
Client reported: deleting a profile (e.g. "Harshil") and then trying to create
a new profile with the same name failed with `"Profile name already taken"`,
even though the old profile was gone from the user's point of view. Root
cause was two layers deep:

1. `creator_profiles.profile_name` had a full `UNIQUE` constraint at the DB
   level — soft-deleting a profile (`status = 'deleted'`) never freed the name.
2. `create_profile` and `update_profile`'s own uniqueness checks matched
   against *all* profiles regardless of `status`, so even after fixing (1)
   they'd still reject the reuse.

**Fixed:**
- `creator_profiles` — dropped the table-level `UNIQUE (profile_name)`
  constraint, replaced with a partial unique index
  `unique_profile_name_active` scoped to `WHERE status != 'deleted'`.
- `create_profile_v2` — uniqueness check now excludes `status = 'deleted'`
  rows. New endpoint `POST /rpc/create_profile_v2`; `v1` kept deprecated for
  backwards compatibility.
- `update_profile_v2` — same fix for the rename-uniqueness check. New
  endpoint `POST /rpc/update_profile_v2`; `v1` kept deprecated.

**Files:**
- [[schema/tables/05_creator_profiles.md]] — dropped UNIQUE constraint, added partial unique index + migration SQL
- [[functions/profiles/create_profile.md]] — added `create_profile_v2`, kept `v1` deprecated
- [[functions/profiles/update_profile.md]] — added `update_profile_v2`, kept `v1` deprecated
- [[docs/api/profiles/create_profile.md]] — endpoint + error-case note updated
- [[docs/api/profiles/update_profile.md]] — endpoint + error-case note updated
- [[docs/database/tables/05_creator_profiles.md]] — business rule updated to describe partial-index uniqueness
